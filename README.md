# Music Renaming & Tagging Pipeline

A safe, two-phase, and resumable pipeline for standardizing and tagging music files (`.mp3`, `.m4a`, `.flac`, `.aac`, `.dsf`, `.wav`, `.ogg`, `.opus`) using optional local LLMs (Ollama) or external cloud LLMs (ChatGPT, Claude, Gemini, DeepSeek).

---

## Key Features

- **Audio & Music Specialization:**
  - Extracts embedded tags: **Artist, Title, Album, Album Artist, Year / Date, Track Number, Disc Number, Genre, Composer, Comments**.
  - Extracts codec-specific audio stream properties: **Codec, Bitrate, Sample Rate, Bit Depth, Channels, DSD clock details (DSD64, DSD128), and Duration**.
  - Supports all major music formats: **MP3, M4A / ALAC, FLAC, AAC, DSF (Sony DSD), WAV, OGG, OPUS, AIFF**.
  - Writes/updates tags directly to audio files upon execution.
- **Customizable Attribute Export:**
  - Choose which metadata tags and technical properties to include when exporting file lists.
  - Export to **JSON** (default, ideal for LLMs), **JSON Lines**, **CSV**, or formatted **Plain Text**.
- **Seamless External LLM Integration:**
  - Includes `input_output_format.txt` documenting the schema and providing copy-paste prompt templates for ChatGPT, Claude, and Gemini.
  - Import external `rename_plan.json` files directly into the GUI or CLI.
- **Optional Local LLM Setup (Windows & Linux):**
  - Dedicated "Local LLM Setup" tab.
  - Using a local LLM is completely optional (disabled by default).
  - Built-in detection for Ollama binaries and server status on both Windows and Linux with first-time setup instructions.
- **Phase 4 Post-Execution Verification:**
  - Automatically verifies destination files on disk, checks non-empty file size, confirms original source disappearance, validates audio stream readability, and verifies written tags.
  - Produces structured timestamped reports: `verification_report_<timestamp>.json`.
- **Safe Apply & Append-Only Rollback:**
  - Always runs as a safe Dry-Run diff simulation first.
  - Requires confirmation before touching disk.
  - Streams atomic rollback logs (`rollback_log_<timestamp>.jsonl`) that record original filenames AND original audio tags for 100% reversible undo.

## Graphical User Interface (PyQt6)

Launch the desktop GUI:

```bash
# Linux
./run_linux.sh
# or
.venv/bin/python src/gui_app.py

# Windows
run_windows.bat
```

### GUI Tabs:
1. **1. Scanner • Raw Files:**
   - Select your target music directory.
   - Fast recursive scanning into a virtualized table displaying Track, Artist, Title, Album, Year, Codec, Bitrate, Duration, and Size.
   - Click **"Export File List..."** to open the export dialog, select desired attributes, and export to JSON/CSV/TXT.
2. **2. AI Renamer • Plan Editor:**
   - Double-click to edit proposed filenames inline.
   - View proposed audio tags, confidence scores, and reasoning in the live Master-Detail Inspector.
   - Click **"Import Plan JSON..."** to import plans generated by external LLMs.
   - If Local LLM is enabled in Tab 4, run local batch inference directly.
3. **3. Safe Apply • Rollback & Verify:**
   - Dry-Run Preview diff dialog showing exact Before ➔ After paths and tag updates.
   - Checkbox safety lock before touching disk.
   - One-click rollback reversing filenames and restoring original tags.
   - Automatic post-execution verification with live pass/fail counts.
4. **4. Local LLM Setup (Optional):**
   - Checkbox to enable/disable local inference (disabled by default).
   - Auto-detects Ollama on Windows and Linux.
   - One-click daemon start/stop, model selection, preloading, and live CPU/RAM monitoring.
5. **5. Logs • Activity Console:**
   - Real-time logging of all scanner, planner, applier, rollback, and verification events.

## CLI Usage

### Phase 0: Scan Music Files (`scan.py`)
```bash
# Scan directory and export JSON with default music attributes
python src/scan.py "/path/to/music" -o data/file_list.json

# Export all 24 attributes
python src/scan.py "/path/to/music" --all-attributes -o data/file_list.json

# Export specific attributes to CSV
python src/scan.py "/path/to/music" -a "relative_path,artist,title,album,year,track_number,codec" -f csv -o data/music.csv
```

### Phase 1: AI Planner (`plan.py`)
```bash
# Using local Ollama (if running)
python src/plan.py --file-list data/file_list.json --rules "Renaming Rules.txt" --batch-size 10

# Test limit of 20 files
python src/plan.py --limit 20
```
*(Or use any external LLM with `input_output_format.txt` and save output to `data/rename_plan.json`)*

### Phase 2: Validate, Dry-Run & Apply (`apply.py`)
```bash
# Step 1: Safe Dry-Run preview (no files or tags modified)
python src/apply.py "/path/to/music" --plan data/rename_plan.json

# Step 2: Apply renames on disk and write audio tags
python src/apply.py "/path/to/music" --plan data/rename_plan.json --execute

# Apply renames without modifying embedded audio tags
python src/apply.py "/path/to/music" --plan data/rename_plan.json --execute --no-tags
```

### Phase 3: Rollback / Undo (`--rollback`)
```bash
# Reverses disk renames AND restores original audio tags
python src/apply.py --rollback data/rollback_log_YYYYMMDD_HHMMSS.jsonl
```

### Phase 4: Verification (`verify.py`)
```bash
python src/verify.py "/path/to/music" --plan data/rename_plan.json
```

## Unified CLI Runner (`pipeline.py`)
```bash
python src/pipeline.py scan "/path/to/music"
python src/pipeline.py plan --limit 20
python src/pipeline.py apply "/path/to/music"           # dry-run diff
python src/pipeline.py apply "/path/to/music" --execute # execute on disk
python src/pipeline.py verify "/path/to/music"          # verify files and tags
python src/pipeline.py rollback rollback_log_XYZ.jsonl # undo
```
