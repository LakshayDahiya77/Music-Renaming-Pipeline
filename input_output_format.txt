================================================================================
MUSIC RENAMING & TAGGING PIPELINE: INPUT / OUTPUT SPECIFICATION
================================================================================

This document specifies the exact data contracts and JSON structures for:
1. INPUT: `file_list.json` (exported by Phase 0 / Scanner)
2. OUTPUT: `rename_plan.json` (produced by any LLM or Phase 1 / Planner)
3. PROMPT TEMPLATE: Ready-to-use prompt to feed into external LLMs
   (ChatGPT, Claude, Gemini, DeepSeek, local models, etc.)

--------------------------------------------------------------------------------
1. INPUT SPECIFICATION: file_list.json
--------------------------------------------------------------------------------
Generated during Phase 0 (Scanner) and exported as a JSON array of audio file
objects. Users can choose which attributes to include during export.

Common supported music formats:
- .mp3  : MPEG-1/2 Audio Layer 3 (ID3v1, ID3v2.3, ID3v2.4)
- .m4a  : Apple Audio Container (AAC-LC or ALAC Apple Lossless, iTunes atoms)
- .flac : Free Lossless Audio Codec (Vorbis Comments, native FLAC streaminfo)
- .aac  : Advanced Audio Coding (Raw ADTS stream with ID3)
- .dsf  : Sony Direct Stream Digital (DSD64, DSD128, DSD256 with ID3v2)
- .wav  : Waveform Audio File Format
- .ogg  : Ogg Vorbis
- .opus : Ogg Opus

Available Attributes / Fields:
- "relative_path"       (string, REQUIRED): Relative path from music base directory.
- "filename"            (string): Current base filename on disk.
- "extension"           (string): File extension (e.g. ".mp3", ".flac", ".dsf").
- "title"               (string): Embedded song title tag.
- "artist"              (string): Embedded performing artist tag.
- "album"               (string): Embedded album / release name tag.
- "album_artist"        (string): Embedded album artist tag.
- "year"                (string): Embedded year or release date (YYYY or YYYY-MM-DD).
- "track_number"        (string): Embedded track index (e.g. "01", "1", "1/12").
- "disc_number"         (string): Embedded disc number (e.g. "1", "1/2").
- "genre"               (string): Embedded musical genre tag.
- "composer"            (string): Embedded composer / songwriter tag.
- "comment"             (string): Embedded comments.
- "format"              (string): Container name ("MP3", "FLAC", "M4A", "DSF", etc.).
- "codec"               (string): Audio stream codec (e.g. "MP3", "FLAC", "AAC", "ALAC", "DSD64").
- "duration_formatted"  (string): Duration in mm:ss or hh:mm:ss format.
- "duration_seconds"    (float) : Duration in raw seconds.
- "bitrate_kbps"        (int)   : Bitrate in kbps (e.g. 320, 1411, 5645).
- "sample_rate_hz"      (int)   : Sample rate in Hz (e.g. 44100, 96000, 2822400).
- "bits_per_sample"     (int)   : Audio bit depth (e.g. 16, 24, 1 for DSD).
- "channels"            (int)   : Channel count (1=Mono, 2=Stereo, 6=5.1).
- "channel_layout"      (string): Human-readable layout ("Stereo", "Mono").
- "codec_details"       (string): Technical summary (e.g. "DSD64 (1-bit / 2.8224 MHz)").
- "file_size_formatted" (string): Human-readable file size (e.g. "45.20 MB").

--------------------------------------------------------------------------------
2. OUTPUT SPECIFICATION: rename_plan.json
--------------------------------------------------------------------------------
The checkpoint and execution plan file expected by Phase 2 (Validator & Applier).
Can be a JSON array of plan objects or a JSON dictionary keyed by `old_path`.

Each item in `rename_plan.json` contains:
- "old_path"           (string, REQUIRED): MUST exactly match the input "relative_path".
- "new_name"           (string, REQUIRED): Standardized target filename including extension.
                       CRITICAL: Must preserve original file extension (.mp3, .flac, .dsf, etc.).
- "final_destination"  (string, OPTIONAL): Relative destination path under the music base directory.
                       If omitted, automatically defaults to {parent_dir}/{new_name}.
- "reasoning"          (string, REQUIRED): Chain-of-thought explanation of parsing and rules applied.
- "confidence"         (string, REQUIRED): "high", "medium", or "low".
                       * "high"   : Auto-appliable without user intervention.
                       * "medium" : Requires user review or --apply-medium flag.
                       * "low"    : Ambiguous or missing tags, flagged for manual triage.
- "new_tags"           (object, OPTIONAL): Proposed cleaned tags to write to the audio file on disk:
                       * "artist"       : string
                       * "title"        : string
                       * "album"        : string
                       * "album_artist" : string
                       * "year"         : string (YYYY or YYYY-MM-DD)
                       * "track_number" : string (2-digit padded: "01", "02")
                       * "disc_number"  : string
                       * "genre"        : string

3. COPY-PASTE PROMPT TEMPLATE FOR EXTERNAL LLMS
--------------------------------------------------------------------------------
Copy and paste the prompt below into ChatGPT, Claude, Gemini, or DeepSeek along
with your exported `file_list.json`:

```markdown
You are an expert music tagging and audio file renaming assistant.
Your task is to standardize messy music file names and metadata tags into clean,
consistent naming conventions.

### NAMING FORMAT CONVENTIONS:
1. Target filename format: "{Track} - {Artist} - {Title}.{ext}"
   - If Track number is known, always pad to 2 digits (e.g. "01", "02", "12").
   - If Track number is unknown, use: "{Artist} - {Title}.{ext}".
   - Preserve clean spacing around hyphens (" - ").
2. Clean Title & Artist:
   - Remove messy rip tags like "[320kbps]", "[FLAC]", "[Remastered 2011]", "(Official Audio)", web URLs.
   - Standardize featuring artists to "ft. Artist" or "feat. Artist".
3. CRITICAL: Preserve the exact original file extension (.mp3, .flac, .m4a, .aac, .dsf, .wav).
4. If ambiguous or missing information, do your best sensible formatting and set "confidence" to "medium" or "low".

### INPUT:
Here is the JSON list of music files:
<PASTE YOUR file_list.json CONTENT HERE>

### OUTPUT REQUIREMENT:
Output a single valid JSON array strictly conforming to the following structure:
[
  {
    "old_path": "<exact relative_path from input>",
    "reasoning": "<brief explanation of naming and tag changes>",
    "new_name": "<new standardized filename with extension preserved>",
    "confidence": "high" | "medium" | "low",
    "new_tags": {
      "artist": "<cleaned artist>",
      "title": "<cleaned title>",
      "album": "<album name>",
      "track_number": "<2-digit track e.g. 01>",
      "year": "<4-digit year>"
    }
  }
]
Do not wrap in explanatory conversational text. Output pure JSON.
```

--------------------------------------------------------------------------------
4. LOADING EXTERNAL PLANS BACK INTO THE PIPELINE
--------------------------------------------------------------------------------
Once the external LLM generates the output:
1. Save the JSON output as `data/rename_plan.json` (or any `.json` file).
2. In the GUI:
   - Go to Tab "2. AI Renamer • Plan Editor".
   - Click "Import Plan JSON..." and select your saved file.
   - All proposed names, confidence scores, and new tags will be loaded,
     validated for collisions/illegal characters, and displayed in the table.
3. In CLI:
   - Run: `python apply.py "/path/to/music" --plan "my_plan.json"` (dry-run preview)
   - Run: `python apply.py "/path/to/music" --plan "my_plan.json" --execute` (executes renames & writes tags)
4. Phase 4 Verification:
   - Automatically runs after execution to ensure all files and audio tags exist
     properly on disk and produces a `verification_report.json`.
